# loyalty-processor
Приложение представляет собой распределённую систему обработки и оплаты заказов с использованием бонусного баланса.

### Архитектура
Система состоит из нескольких микросервисов:
* Orders — создание и обработка заказов.
* Inventory — управление остатками товаров.
* Payments — списание бонусов с баланса пользователя и обработка платежей.

Каждый микросервис построен по принципу hexagonal architecture(ports & adapters), каждый слой изолирован друг от друга и взаимодействие происходит через интерфейсы. Это позволяет системе быть хорошо масштабируемой. Также в каждом микросервисе реализован graceful и корректная остановка горутин при помощи context и wg.

### Технологический стек
* Go
* PostgreSQL
* Apache Kafka
* gRPC
* Docker
* Goose
* GolangCI-lint

### Детали реализации
orders принимает заказ от клиента через HTTP и отправляет RPC-запрос в inventory для резервирования товара. После успешного резервирования Orders асинхронно публикует событие о создании заказа в Payments через transactional outbox. payments получает событие из kafka и в рамках одной транзакции обрабатывает платеж. Если на балансе пользователя недостаточно бонусов, payments формирует событие с failed-статусом. Если бонусов достаточно, сервис атомарно создаёт запись о платеже и списывает бонусы с баланса. После этого результат операции сохраняется в outbox и асинхронно публикуется в kafka в топик payments. orders слушает payments и обновляет статус заказа. При неуспешной оплате orders инициирует освобождение ранее зарезервированного товара через Inventory. Система реализует saga-подобный workflow с оркестрацией на стороне orders. Для надёжной доставки событий между сервисами используется transactional outbox, а для защиты от повторной обработки — идемпотентность операций при помощи constraits.

### Запуск
Перед запуском система заполняется seed data для inventory и payments(формирование баланса пользователя). Данные про пользователя и продукт стоит взять из соответствующей базы данных сервиса(inventory, payments).

Система работает на:
```zsh
http://localhost:8080
```

Kafka UI доступна на:
```zsh
http://localhost:4200
```

Доступные ручки:
```zsh
POST http://localhost:8080/api/v1/orders/{product id} # - Создание заказа. JSON - {"amount": integer}
Cookie: userId=...

GET http://localhost:8080/api/v1/orders # Получение всех заказов.
Cookie: userId=...
```

Для удобной локальной работы были описаны Makefile таргеты:
```zsh
make infrastructure #	Запуск инфраструктуры.
make create_topics	# Создание Kafka топиков(orders, payments).
make migrate_up	    # Поднятие миграций.
make seed	        # Заполнение баз данных тестовыми данными.
make up	            # Запуск основных сервисов(orders, inventory, payments).
make lint           # Запуск линтера.
make clean          # Полная остановка + удаление проекта.
make proto          # Генерация protobuf файлов.
```

Запустить одной строкой:
```zsh
make infrastructure && make migrate_up && make seed && make create_topics && make up
```
